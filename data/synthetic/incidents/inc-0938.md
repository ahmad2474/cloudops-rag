# INC-0938: Ledger migration locked `ledger_entries` for 12 minutes

## Summary
Flyway migration `V214__entries_currency_not_null.sql` ran
`ALTER TABLE ledger_entries ALTER COLUMN currency SET NOT NULL` on a 1.1 B-row table. Postgres
took an `ACCESS EXCLUSIVE` lock and scanned the table; every write to the ledger blocked.

## Impact
All payments requiring a ledger write failed for 12 min (≈ 4,100 attempts; most retried by
clients). SEV-1 by definition (core flow).

## Timeline (UTC)
- 09:00 ArgoCD pre-sync hook runs `dbre-migrate` for `ledger-service` v2025.05.27.1.
- 09:02 `ledger-service` p99 → 30 s (statement timeout); `payments-api` 5xx. Page.
- 09:06 `pg_stat_activity`: migration holding `AccessExclusiveLock`; 600+ waiters.
- 09:14 `pg_terminate_backend` on the migration PID (IC approval); lock released.
- 09:16 Writes flowing; resolved. Flyway marked the migration failed; repaired at 11:00.

## Root cause
Migration not written expand/contract. `lock_timeout` was 0 for the migration role, so it
waited/held indefinitely.

## Remediation
Re-implemented as: add `CHECK (currency IS NOT NULL) NOT VALID` → `VALIDATE CONSTRAINT`
(no exclusive lock) → `SET NOT NULL` (fast, uses the validated constraint on PG ≥ 12).

## Prevention
- `dbre-migrate` sets `lock_timeout = 5s` and `statement_timeout = 60s` for DDL.
- Migration review checklist: any `ALTER TABLE` on tables > 10 M rows needs DBRE sign-off.
- Documented in `database-platform` § Schema migrations.
