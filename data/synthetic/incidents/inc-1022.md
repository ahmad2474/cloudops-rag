# INC-1022: Month-end reporting aggregation starved `general` nodes

## Summary
The 1 Jan month-end aggregation ran with 12 parallel workers on `general` nodes (no
toleration for the `memory` pool). Node CPU hit 95%; `ledger-service` pods on the same
nodes saw p99 1.4 s (limit 800 ms).

## Impact
Ledger API latency SLO breached ~100 min at low traffic; no errors.

## Root cause
Batch workload co-located with latency-sensitive services; no CPU limit on the batch job.

## Remediation
Job throttled to 4 workers mid-run.

## Prevention
Aggregation moved to the `memory` pool (toleration + selector, standard §13);
`priorityClassName: batch-low`; CPU limit set for batch.
