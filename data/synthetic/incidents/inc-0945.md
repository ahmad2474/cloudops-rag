# INC-0945: reporting-api pod Pending — EBS volume in a different AZ

## Summary
`reporting-api`'s single-replica cache pod uses an EBS-backed PVC in `us-east-1b`. During a
node rollout all 1b `general` nodes were cordoned; the pod was evicted and stayed Pending with
`volume node affinity conflict`.

## Impact
Report generation paused 36 min; no customer-facing errors (async).

## Root cause
Single-AZ persistent volume + rollout that temporarily removed all schedulable capacity in
that AZ.

## Remediation
Uncordoned one 1b node; pod scheduled.

## Prevention
Rollouts drain one AZ at a time but keep ≥ 1 schedulable node per AZ (managed node group
`maxUnavailable: 1` per AZ via update config). Cache moved to ElastiCache (2025-07).
