# INC-0984: Staging nodes capped at 29 pods after prefix delegation rollout

## Summary
Prefix delegation was enabled on staging (`ENABLE_PREFIX_DELEGATION=true`) but the node
group was not recycled, so kubelet's `max-pods` stayed at the non-prefix value (29 for
`m6i.large`). Pods went Pending with `Too many pods` while IPs were plentiful.

## Impact
Staging capacity halved for 90 min.

## Root cause
Prefix delegation affects max-pods only for nodes launched after the change (bootstrap
computes it); existing nodes keep the old allocatable.

## Remediation
Rolled the node group; new nodes report `allocatable.pods: 110`.

## Prevention
Runbook step: enabling prefix delegation **requires** a node rollout; verify
`kubectl get node -o custom-columns=NAME:.metadata.name,PODS:.status.allocatable.pods`.
(Same mechanism bit prod via Karpenter in INC-1042.)
