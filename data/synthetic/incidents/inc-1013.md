# INC-1013: ExternalSecrets failing in `us-east-1c`

## Summary
The Secrets Manager interface endpoint had ENIs only in 1a and 1b (the 1c subnet was
dropped in a refactor of the endpoints module). With private DNS, `secretsmanager.us-east-1.amazonaws.com`
resolved to the endpoint IPs; pods in 1c could reach them cross-AZ **until** the 1c NACL
change at 07:20 blocked cross-AZ endpoint traffic. ESO syncs in 1c failed; new pods there
started without secrets.

## Impact
`notification-worker` and `ledger-service` pods scheduled to 1c crash-looped for 55 min
(~1/3 of capacity).

## Root cause
Endpoint subnet list not per-AZ; NACL change exposed it.

## Remediation
Added the 1c subnet to the endpoint; NACL change reverted.

## Prevention
`modules/acme-vpc` requires an endpoint subnet per AZ (validation block); Reachability
Analyzer checks per AZ for `secretsmanager`, `sts`, `ecr`.
