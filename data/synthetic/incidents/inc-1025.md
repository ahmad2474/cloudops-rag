# INC-1025: ImagePullBackOff in prod — ECR endpoint private DNS disassociated

## Summary
A network-stack apply that split endpoints into a new stack recreated the `ecr.dkr`
interface endpoint. For ~40 min `private_dns_enabled` was false on the new endpoint;
`*.dkr.ecr.us-east-1.amazonaws.com` resolved to public IPs, which the private-app route
tables reach via NAT — but the bucket-style endpoint policy on the old endpoint had been
the only thing allowing the pull path through the SCP's `aws:SourceVpce` condition for ECR.
Result: `ErrImagePull: 403 Forbidden` for any pod scheduled during the window.

## Impact
No running pods affected; 9 pods (HPA scale-out, one rollout) failed to start for 45 min.

## Root cause
Endpoint recreated without private DNS; SCP condition on ECR requiring the VPC endpoint.

## Remediation
`private_dns_enabled = true`; apply; pods pulled within 2 min.

## Prevention
Endpoint moves use `moved` blocks (no recreation); Checkov custom check requires
`private_dns_enabled` on interface endpoints; deploy freeze during network applies.
