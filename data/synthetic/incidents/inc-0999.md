# INC-0999: checkout-web 502s on every deploy

## Summary
Every `checkout-web` rollout produced a burst of ~200 ALB 502s. Two mechanisms: Node.js's
default `keepAliveTimeout` (5 s) is shorter than the ALB idle timeout (60 s), so the ALB
reused connections the app had closed; and pods exited on SIGTERM immediately, dropping
in-flight requests while still registered in the target group.

## Impact
~0.3% of checkout requests failed during each of ~15 deploys over a month; noticed when the
canary analysis threshold was tightened.

## Root cause
Keep-alive mismatch + no graceful drain.

## Remediation
`server.keepAliveTimeout = 65000`, `headersTimeout = 66000`; `preStop: sleep 10`;
`terminationGracePeriodSeconds: 45`; `deregistration_delay 30`.

## Prevention
Documented in `alb-ingress-502`; base Node image sets keep-alive defaults; standard §11.
