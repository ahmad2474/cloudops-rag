# INC-0925: NAT gateway saturation in us-east-1b

## Summary
A new `data-pipeline` job pulled a 1.8 TB public dataset through `nat-prod-use1-b` at
~5 Gbps. `ErrorPortAllocation` rose on the NAT and outbound calls from other 1b workloads
(`payments-api` → PSP, `webhook-dispatcher` → merchants) timed out.

## Impact
Payment authorisations from 1b pods failed 6% for 35 min; webhooks delayed. SLO budget: 18%.

## Timeline (UTC)
- 13:05 Job starts (8 parallel workers on 1b memory nodes).
- 13:20 `payments-api` error-rate alarm; NAT `ErrorPortAllocation` > 0 and `BytesOutToDestination` at 5 Gbps.
- 13:40 Job suspended; errors clear within 3 min.
- 14:15 Resolved.

## Root cause
Bulk internet egress shared a NAT with latency-sensitive traffic; no egress QoS. 5 Gbps also
exceeded the NAT's sustained baseline for port allocation with a single destination IP.

## Remediation
Dataset moved to an S3 bucket (one-time copy via a dedicated egress instance); job reads via
the S3 gateway endpoint (no NAT).

## Prevention
- Policy: internet bulk transfers > 100 GB go through the `egress` stack (separate NAT + subnet), not app NATs.
- Alarm on `ErrorPortAllocation > 0` and `PacketsDropCount` per NAT.
- Cost note: the pull would have cost ~$80 in NAT processing; S3 gateway path cost $0.
