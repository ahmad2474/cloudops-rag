# INC-1063: Leaked CI token used against `acme-prod-customer-documents`

**RESTRICTED — SecEng.**

## Summary
A GitHub PAT committed to a public fork of `acme-infra` was used to run a workflow that
assumed the legacy role `acme-prod-ci-legacy` (long-lived access key `AKIA…LEGACY` stored
as a repository secret). The actor attempted 1,912 `GetObject` calls on the customer
documents bucket — **all denied** by the KMS key policy and the `aws:sourceVpce` bucket
condition — and 3 successful `ListBucket` calls (opaque keys only).

## Impact
No customer document contents accessed. No regulatory notification required (Legal, 05-09).

## Timeline (UTC)
- 05-05 22:14 PAT pushed to public fork.
- 05-07 08:12 GuardDuty `Discovery:S3/AnomalousBehavior` → `sec-oncall`.
- 08:31 `AcmeDenyAll` on the role; key deactivated; PAT revoked.
- 09:10 Full rotation per `production-credential-rotation`.
- 09:58 Containment confirmed; forensics exported.

## Root cause
Legacy long-lived credential left behind by the OIDC migration; push protection not
org-enforced for forks.

## Remediation / Prevention
See `postmortem-inc-1063`: role deleted, org-wide push protection, `secret-management` v2.0,
GuardDuty Discovery findings page.
