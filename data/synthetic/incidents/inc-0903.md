# INC-0903: checkout-web 503s during deploy

## Summary
A release renamed the health endpoint from `/healthz` to `/health` in the app but not in
the Helm values. New pods never became Ready; as the rollout proceeded the ALB target group
drained to zero healthy targets and returned 503 for 18 minutes.

## Impact
Checkout page unavailable for ~40% of sessions (the rollout was at 40% when it stalled and
old pods were terminated by `maxUnavailable: 25%`). Availability SLO for the month: 62% budget consumed.

## Symptoms
- ALB 503, target group healthy count falling
- `Readiness probe failed: HTTP probe failed with statuscode: 404`

## Timeline (UTC)
- 13:58 ArgoCD sync of `checkout-web` v2025.03.11.1 (manual, in window).
- 14:03 Alarm `checkout-alb-5xx`. Page `growth-oncall`.
- 14:09 Events show 404 on readiness; rollback initiated in ArgoCD.
- 14:21 All old-version pods Ready; 503s stop.

## Root cause
Readiness probe path drift between application code and chart values; the deployment
strategy allowed old pods to terminate before new ones were Ready.

## Remediation
Rollback; fix values; redeploy at 15:10 without issue.

## Prevention
- `maxUnavailable: 0` for customer-facing Deployments (now a lint rule).
- Argo Rollouts canary for `checkout-web` (done 2025-04) — a 10% step would have aborted.
- Health endpoint path comes from a single chart value consumed by both app config and probe.
