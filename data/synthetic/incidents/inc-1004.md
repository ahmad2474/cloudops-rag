# INC-1004: `prod-ledger-pg` Multi-AZ failover; apps with cached DNS stuck on old primary

## Summary
An AWS host issue triggered an automatic Multi-AZ failover (completed in 68 s). `ledger-service`
(JVM) kept connecting to the old primary's IP for 30+ min because the JVM cached DNS
indefinitely (`networkaddress.cache.ttl` unset, security manager default). `reporting-api`
(Go) recovered in seconds.

## Impact
Ledger writes failed 36 min at ~02:00 UTC (low traffic; 140 payments affected, all retried).

## Root cause
Client-side DNS caching ignoring the 30 s TTL of `ledger-pg.prod.acme.internal`.

## Remediation
`kubectl rollout restart deploy/ledger-service -n ledger`.

## Prevention
JVM base image sets `-Dnetworkaddress.cache.ttl=30`; failover game-day added to the
quarterly DR test; `rds-connection-failure` §1 updated.
