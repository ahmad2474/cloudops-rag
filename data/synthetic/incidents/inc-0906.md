# INC-0906: Terraform state lock stuck after Atlantis pod OOM

## Summary
The Atlantis pod was OOMKilled mid-apply on the `acme-prod/us-east-1/eks` stack. The
DynamoDB lock item remained; subsequent plans failed with `Error acquiring the state lock`.

## Impact
Infra changes blocked for 30 min. No production impact; the apply had not started modifying
resources (it died during refresh).

## Timeline (UTC)
- 11:31 Atlantis `apply` on PR #1412.
- 11:33 Atlantis pod restarted (`OOMKilled`, limit 2 Gi).
- 11:40 Next plan fails on lock (ID `a91e…`, `Who: atlantis@atlantis-0`).
- 11:55 Confirmed no apply in progress; PE on-call approved force-unlock in `#platform`.
- 12:02 `terraform force-unlock a91e…` from a Gatekeeper session; plan re-run clean; state verified against the S3 version list.
- 12:10 Resolved.

## Root cause
Atlantis memory limit too low for the EKS stack refresh (many `aws_eks_addon` data sources).

## Remediation
Atlantis limit 2 → 4 Gi; `TF_PLUGIN_CACHE_DIR` enabled to cut memory.

## Prevention
`terraform-state-lock-recovery` runbook written from this incident.
