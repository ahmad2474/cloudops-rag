# INC-1031: Login outage — identity-service JWKS rotation served stale keys

## Summary
Scheduled signing-key rotation in `identity-service` published the new JWKS, but an
in-process cache with a 1-hour TTL kept **signing** with the new key while the public
JWKS endpoint (served from a separate replica set) still returned the old set. Every
downstream service rejected new tokens (`kid not found`).

## Impact
All logins and token refreshes failed for 35 min. SEV-1. ~18k users affected; merchant
dashboards and checkout (guest flow unaffected) down.

## Timeline (UTC)
- 11:00 Rotation job runs.
- 11:04 `token_validation_failures` alarm; page identity + payments.
- 11:12 Hypothesis: JWKS cache. Confirmed `kid` mismatch between `/token` and `/.well-known/jwks.json`.
- 11:25 Rolled restart of the JWKS-serving replicas; downstream caches refreshed on 401 retry.
- 11:39 Resolved.

## Root cause
Two replica sets with independent caches; rotation updated one path atomically but not the
other. Downstream JWKS caches did not refetch on unknown `kid`.

## Remediation
Restart; then hotfix: publish new key in JWKS 24 h **before** signing with it (key
pre-announcement), downstream libs refetch on unknown `kid`.

## Prevention
Rotation runbook for signing keys; canary token validation check post-rotation; game-day.
