# INC-0921: S3 AccessDenied on ledger exports after `aws:sourceVpce` condition added

## Summary
SecEng added a bucket-policy condition requiring `aws:sourceVpce = vpce-0a1b…` on
`acme-prod-ledger-exports`. Pods in `us-east-1c` failed with 403 because the S3 gateway
endpoint route was missing from the 1c private-app route table, so their traffic exited via NAT.

## Impact
Nightly ledger export partially failed (1c shard); reporting for 22 Apr delayed 4 h.

## Symptoms
`AccessDenied` only from pods on 1c nodes; CloudTrail `vpcEndpointId` absent on denied calls.

## Root cause
Route table for 1c was created after the endpoint and never associated with it (manual fix
from 2024 that Terraform didn't track). The policy change exposed the latent gap.

## Remediation
Associated the gateway endpoint with the 1c route table (Terraform).

## Prevention
- `modules/acme-vpc` associates gateway endpoints with **all** private route tables from a map.
- Drift job now covers route table associations.
- Policy changes with network conditions require a Reachability Analyzer check per AZ.
