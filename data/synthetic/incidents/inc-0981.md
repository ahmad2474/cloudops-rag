# INC-0981: Cluster-wide pod IP exhaustion in `prod-use1-a`

## Summary
The private-app subnets (/20 per AZ) that supplied pod IPs ran out, starting in
`us-east-1a`. No new pod could start for 2.5 h: rollouts stalled, HPA could not scale,
and adding nodes made it worse (each node consumed IPs and failed to attach secondary IPs).

## Impact
`checkout-web` at 60% capacity mid-rollout (p99 breached 90 min); notification backlog 2.1 M;
no payment failures.

## Symptoms
- Pods `Pending`/`ContainerCreating` with `failed to assign an IP address to pod`
- `AvailableIpAddressCount` on 1a private-app subnet: 3
- `awscni_no_available_ip_addresses` > 0 across 1a nodes

## Investigation
Followed the 1.28-era runbook (`WARM_IP_TARGET`) — insufficient because no unused IPs
existed in 1a. Scaling the node group consumed the last addresses.

## Root cause
Pod density outgrew the subnet plan; pods shared address space with node ENIs; no headroom alarm.

## Remediation
Added secondary CIDR `100.64.0.0/16` + per-AZ pod subnets + `ENIConfig`s (custom
networking) during the incident; rolled nodes. Prefix delegation enabled 2025-09-02.

## Prevention
Subnet headroom alarms, quarterly capacity review, rewritten runbook, Karpenter adoption.
Full analysis: `postmortem-inc-0981`.
