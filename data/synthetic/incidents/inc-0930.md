# INC-0930: identity-service p99 tripled after a CPU limit was added

## Summary
A "hardening" PR added `resources.limits.cpu: 500m` to `identity-service` (request 500m).
Token issuance p99 went from 180 ms to 620 ms; CPU usage per pod stayed at ~300m, which sent
the on-call down a database path first.

## Impact
Login latency SLO (p99 < 250 ms) breached for 100 min; login success rate unaffected.

## Investigation
Grafana `container_cpu_cfs_throttled_periods_total` ratio: 68%. JVM with 8 GC threads on a
0.5-core quota stalls on every young-gen collection.

## Root cause
CFS throttling from a CPU limit on a multi-threaded latency-sensitive service.

## Remediation
Limit removed (request kept at 500m). p99 back to 175 ms within one rollout.

## Prevention
`kubernetes-workload-standards` §2: no CPU limits on `payments-api`, `identity-service`,
`checkout-web`; `cpu-throttling` page written.
