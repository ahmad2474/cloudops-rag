# INC-0914: Pods Pending after node group rotation — stale toleration

## Summary
The `workers` managed node group (taint `workload=workers:NoSchedule`) was retired and
merged into `general`. `notification-worker` and `webhook-dispatcher` still carried
`nodeSelector: acme/pool=workers` from their chart; once the last `workers` node drained,
every new pod stayed `Pending`. Cluster CPU and node count looked normal.

## Impact
Notification and webhook delivery paused ~65 min; backlog of 380k messages processed by 17:40.
No data loss.

## Symptoms
`0/44 nodes are available: 44 node(s) didn't match Pod's node affinity/selector`.
No IP or capacity errors — this is **not** a networking incident despite the "Pending" symptom.

## Timeline (UTC)
- 14:50 Terraform apply removes `workers` node group (change ticket approved).
- 15:22 Queue-depth alarm for notifications. Page `growth-oncall`, then PE.
- 15:40 Events read; `nodeSelector` found in the chart.
- 16:05 Values patched (selector removed), ArgoCD sync.
- 16:30 All pods Running; resolved.

## Root cause
Node pool removal without auditing which workloads targeted it.

## Remediation
Chart fix; `acme/pool` label retired.

## Prevention
- Pre-change check: `kubectl get pods -A -o json | jq` for selectors/tolerations matching the pool being removed (added to the node-group change template).
- `pods-pending` troubleshooting page lists this case first.
