# INC-0956: fraud-scoring OOMKilled after model size increase

## Summary
A new fraud model (2.4 GB vs 1.1 GB) shipped without a memory limit change (4 Gi). All three
replicas entered `CrashLoopBackOff` with `OOMKilled` during model load. `payments-api`
fails open to a rules-only score when scoring is unavailable, so payments continued with
reduced fraud coverage.

## Impact
40 min of degraded fraud scoring; 3 transactions later flagged by manual review.

## Root cause
Memory limit not sized for the new model; no load test of memory in staging (staging used the
old model artefact due to a promotion bug).

## Remediation
Rollback; redeploy with 8 Gi limit on the `memory` pool.

## Prevention
Model registry records peak RSS; deploy pipeline fails if limit < 1.5× recorded peak.
